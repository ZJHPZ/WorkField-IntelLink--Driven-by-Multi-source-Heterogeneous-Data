### 结论 5：Pinia Store 的"API 静默回退"模式是核心架构

```typescript
// user.ts 的标准模式 —— 每个 store 都必须复制
const profile = ref(isAdmin ? demoAdminProfile : demoLearnerProfile)

async function fetchProfile() {
  try {
    const res = await client.get('/api/user/profile')
    if (res) { profile.value = res; return }
  } catch {}
  // 静默回退到初始化时设置的演示数据
}
```

**关键洞察**：不是在 `catch` 里才设置 demo 数据——而是**初始化时就用 demo 数据填充**。API 成功时覆盖，失败时静默保留。这意味着前端启动即展示完整 UI，无需等待后端。

## 2. 关键组件源码解读

### 2.1 CosmicBackground.vue —— 构建宇宙背景的 4 层结构

```vue
<!-- 第1层：深空底色 -->
<!-- 关键：不是纯黑 #000，是径向渐变模拟星云 -->
radial-gradient(ellipse at 30% 20%, #1a1040 0%, #0a0a18 40%, #050510 70%, #020208 100%)

<!-- 第2层：星云光晕（4个椭圆径向渐变光斑） -->
<!-- 关键：超大尺寸(250-400px) + 极低透明度(6-12%) -->
radial-gradient(ellipse 400px 300px at 20% 30%, rgba(99,102,241,0.12) 0%, transparent 60%)

<!-- 第3层：星空粒子(80个CSS div) -->
<!-- 关键：确定性种子算法，避免渲染闪烁 -->
const seed = i * 17 + (i % 11) * 3
// 白色为主(80%)，偶有靛蓝/青/紫色(20%)
// 50%的星星带 twinkle 动画

<!-- 第4层：流动数据光线(3水平+2垂直) -->
<!-- 关键：opacity 6%，极低，不分散注意力 -->
animation: dataFlowH 8s linear infinite;
animation: dataFlowV 9s linear infinite;
```

### 2.2 ProgressRing.vue —— SVG 渐变进度环

```
关键参数：
- size: 120px (默认), strokeWidth: 8px
- circumference = 2 * PI * radius
- offset = circumference - (percentage/100) * circumference
- 过渡：stroke-dashoffset 0.8s cubic-bezier(0.4, 0, 0.2, 1)
- 渐变：linearGradient indigo→purple→cyan

职域智联使用场景：
- 企业侧：不直接使用
- 个人侧：匹配率展示（中心文字=72%）
```

### 2.3 EnergyBar.vue —— 5 变体进度条

```
variant 映射：
  brand:  indigo 填充 + indigo 文字   → 通用进度
  mint:   薄荷绿填充 + 薄荷绿文字      → "健康"
  amber:  琥珀色填充 + 琥珀色文字      → "需关注"
  rose:   玫瑰色填充 + 玫瑰色文字      → "严重"
```

## 3. Pinia Store 实施模式

### 3.1 核心模式：初始化即 Demo

```typescript
// 参考 stores/user.ts 的模式 —— 不是"先加载后回退"，而是"先填充后覆盖"
export const useEnterpriseStore = defineStore('enterprise', () => {
  // 第1步：检测当前角色
  const isEnterprise = true // 企业侧永远为企业模式

  // 第2步：用演示数据初始化（不是 null，不是 undefined）
  const dashboard = ref<DashboardData>(demoDashboard)
  const positions = ref<PositionStandard[]>(demoPositions)
  const candidates = ref<RoleCandidate[]>(demoCandidates)

  // 第3步：异步加载真实数据，失败时静默保留演示数据
  async function fetchDashboard() {
    try {
      const res = await client.get('/api/enterprise/dashboard')
      if (res && res.positionCount > 0) { dashboard.value = res }
    } catch { /* 静默保留demo数据 */ }
  }

  async function fetchPositions() {
    try {
      const res = await client.get('/api/positions')
      if (res && res.positions?.length > 0) { positions.value = res.positions }
    } catch {}
  }

  return { dashboard, positions, candidates, fetchDashboard, fetchPositions }
})
```

### 3.2 演示数据质量要求

```
数知的演示数据经验：
- 每个 store 都有完整的、真实的、可直接渲染的 demo 数据
- demo 数据量 = 真实数据量（不是 1-2 条样板）
- admin 用户的 demo 数据展示"完美状态"（全部完成/高级别）
- learner 用户的 demo 数据展示"进行中状态"（部分完成/中级）

职域智联对应：
- 企业侧 demo：12 个岗位标准 + 3 个候选 + 2 个差异报告 + 50 条诊断记录
- 个人侧 demo：12 项技能 + 3 个岗位匹配 + 2 条保鲜预警 + 1 份转行分析
```
