> 版本：v2.0 | 2026-08-02

## 1. 架构总览

```
                          FastAPI 端点
                               │
                               ▼
                    ┌─────────────────────┐
                    │  MultiAgentSystem   │  ← 主入口（单例）
                    │  system.process()   │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
        IntentRouter      AgentRegistry    AgentExecutor
        (意图->Agent)     (注册+依赖图)    (联邦式/协作式)
              │                │                │
              └────────────────┼────────────────┘
                               │
              ┌────────────────┴────────────────┐
              │                                 │
    ┌─────────┴──────────┐          ┌──────────┴──────────┐
    │  Federated Agents  │          │ Collaborative Agents│
    │  (独立并行执行)     │          │  (依赖链顺序执行)    │
    ├────────────────────┤          ├─────────────────────┤
    │ ExtractAgent       │          │ MatchAgent          │
    │ VerifyAgent        │          │ DiscoveryAgent      │
    │ NormalizeAgent     │          │ SuggestAgent        │
    │ JudgeAgent         │          │ OrchestratorAgent   │
    │ EvolutionAgent     │          │                     │
    └────────────────────┘          └─────────────────────┘
```

### 1.1 核心原则

- **意图驱动**：每个 Agent 声明 `intent_type`——API 端点决定意图，Router 自动路由
- **模式分离**：Federated（独立并行）vs Collaborative（依赖链顺序）
- **LLM 嵌入**：Agent 通过 `llm_client` 拥有独立推理能力，关键决策点调用星火
- **状态传递**：`MultiAgentState` 携带 payload + agent_results，Agent 间通过 state 通信

### 1.2 数据流

```
API 请求
  → MultiAgentState(payload={...})
  → IntentRouter.route(intent) → agent_id
  → AgentExecutor.execute(intent, payload)
    → Federated: agent.process(state) 直接执行
    → Collaborative: chain = [dep1, dep2, agent] 顺序执行
      → 每个 Agent 的结果写入 state.agent_results
  → 返回最终结果
```

## 3. 每个智能体详细设计

### 3.1 ExtractAgent —— 技能抽取

```
agent_id:     extractor
模式:         Federated
意图:         EXTRACT_SKILLS
LLM:          星火 Spark-X2-Flash
依赖:         无
```

**职责**：从 L1 清洗后的 JD 中抽取原子化技能，每条带原文证据。

**LLM 调用**：
- `l3_extract.py` 构建 Prompt → 星火 `extract_json()` → 返回 `[{skill, type, evidence}]`
- 失败/空结果 → 规则 `_rule_extract()` 兜底

**系统提示词**（`l3_extract.py:_EXTRACT_SYSTEM`）：
```
你是招聘数据分析师。从给定的岗位要求文本中抽取技术技能与硬性要求。
只能抽取文本中真实出现的技能，禁止编造或补充文本外的技能。
```

**输入/输出**：
```
输入: CleanedJD {title, candidates: [(section, phrase, level, category), ...]}
输出: {skills: [ExtractedSkill{name, required_type, evidence, source}], count: N}
      source="spark" 表示 LLM 抽取, source="rule" 表示规则兜底
```

---

### 3.2 VerifyAgent —— 幻觉闸门

```
agent_id:     verifier
模式:         Federated
意图:         VERIFY_SKILLS
LLM:          无（纯规则，by design）
依赖:         无
```

**职责**：对抽取结果过三道闸——拦截无证据/伪造证据/证据不支撑的技能。

**三道闸门**：
- 闸1（强制引证）：evidence 非空
- 闸2（证据核验）：evidence 原文必须在 JD 中真实存在
- 闸3（内容核验）：evidence 必须字面包含该技能名

**输入/输出**：
```
输入: {extracted_by_jd: [(jd_id, tech_stack, [ExtractedSkill])], jd_fulltext_map: {jd_id: text}}
输出: {verified_by_jd: [(jd_id, tech_stack, [passed skills])],
       gate_total: N, gate_rejected: M, intercept_rate: M/N, reject_log: [...]}
```

**设计理念**：规则而非 LLM——闸门本身不能成为新的幻觉源。可复现、可审计、不烧 API。

---

### 3.3 NormalizeAgent —— 技能归一化

```
agent_id:     normalizer
模式:         Federated
意图:         NORMALIZE_SKILLS
LLM:          无（别名表+频次统计，by design）
依赖:         无
```

**职责**：将过闸技能归一到规范名，统计 DF/置信度/验证状态。

**归一化步骤**：
1. 剥离信号词前缀（"熟悉Python" → "Python"）
2. 大小写统一 + 中英文空格压缩
3. 查别名映射表 `SKILL_ALIASES`（k8s → Kubernetes）
4. 未收录词保持原样，后续 embedding 聚类接管

**输入/输出**：
```
输入: {verified_by_jd: [(jd_id, tech_stack, [ExtractedSkill])]}
输出: {skill_stats: {规范名: SkillStat{df, confidence, verification_status, required_count, bonus_count}}}
      unique_skills: N
```

---

### 3.4 MatchAgent —— 人岗匹配

```
agent_id:     matcher
模式:         Collaborative
意图:         MATCH_POSITION
LLM:          无（Jaccard + 加权算法，by design）
依赖:         [extractor, normalizer]
```

**职责**：用户技能 vs 岗位要求 → 匹配评分 + 缺失清单 + 学习路径。

**匹配算法**：
1. 归一化双方技能名
2. Jaccard 匹配率 + 必备/加分加权
3. 必备技能权重 60%，技能覆盖率权重 40%
4. 识别部分匹配（子串/模糊）和完全缺失

**输入/输出**：
```
输入: {user_skills: [str], position_skills: [{name, required_type, confidence}]}
输出: {match_rate: 0.72, matched_skills: [...], missing_skills: [{name, priority, reason}],
       learning_path: [{step, skill, duration, resources}]}
```

### 3.5 DiscoveryAgent —— 新岗发现（正方）

```
agent_id:     discoverer
模式:         Collaborative
意图:         DISCOVER_ROLE
LLM:          星火 Spark-X2-Flash
依赖:         [normalizer]
```

**职责**：分析新兴技能聚类 + JD 证据 → 提出候选岗位定义（5 字段）。

**系统提示词**（`discovery_agent.py:DISCOVERY_SYSTEM`）：
```
你是一个新兴岗位发现专家。
基于提供的证据（新兴技能列表+相关JD片段），为一个候选新岗位生成定义。
输出 JSON：
{
  "岗位名称": "...",
  "核心职责": {"value": "...", "evidence_ids": [...]},
  "必备技能": {"value": ["技能1"], "evidence_ids": [...]},
  "加分技能": {"value": [], "evidence_ids": [...]},
  "典型行业应用场景": {"value": ["场景1"], "evidence_ids": [...]},
  "argument": "为什么这是一个真正的新岗位"
}
规则：每个字段必须基于证据。证据不足时降低置信度而非编造。
```

**输入/输出**：
```
输入: {debate_topic: {term, emerging_skills, evidence_jds}}
输出: {term, definition: {岗位名称, 核心职责, 必备技能, 加分技能, 典型行业应用场景, argument},
       evidence_count: N, skill_count: M}
```

### 3.6 JudgeAgent —— 辩论裁决

```
agent_id:     judge
模式:         Federated
意图:         DISCOVER_ROLE
LLM:          星火 Spark-X2-Flash
依赖:         无
```

**职责**：综合正方论点（DiscoveryAgent）和反方质疑（Skeptic逻辑），做最终裁定。

**裁决规则（确定性层）**：
- evidence_count >= 10 AND skill_count >= 3 AND high_concerns == 0 → Confirmed
- evidence_count < 5 → Rejected
- 其他 → Pending

**系统提示词**（`judge_agent.py:JUDGE_SYSTEM`）：
```
你是一个公正的岗位审核裁判。
判定标准：
- Confirmed: 支撑JD>=10条, 技能>=3项可区分, 反方无high级质疑
- Pending: JD 5-9条, 或存在medium级质疑需补充证据
- Rejected: JD<5条, 或>=2个high级质疑
输出 JSON: {"verdict": "Confirmed|Pending|Rejected", "reason": "...", "next_steps": [...]}
```

**输入/输出**：
```
输入: {pro_argument, con_argument, debate_topic}
输出: {verdict: Confirmed|Pending|Rejected, reason, evidence_count,
       skill_count, high_concerns, next_steps}
```

### 3.7 SuggestAgent —— 职业建议

```
agent_id:     suggester
模式:         Collaborative
意图:         CAREER_GAP
LLM:          星火 Spark-X2-Flash
依赖:         [matcher]
```

**职责**：基于人岗匹配差距 → 生成分步骤学习路径。

**系统提示词**（`suggest_agent.py:SUGGEST_SYSTEM`）：
```
你是职业规划专家。基于用户技能与目标岗位的差距，生成学习路径。
输出 JSON: {
  "match_rate": 0.0-1.0,
  "matched_skills": [],
  "missing_skills": [{"name":"","priority":"高|中|低"}],
  "learning_path": [{"step":1,"skill":"","duration":"X-Y个月","resources":[]}]
}
```

**输入/输出**：
```
输入: {user_skills, position_skills, position_name}
输出: {missing_skills: [...], learning_path: [{step, skill, duration, resources}], total_missing: N}
```

### 3.8 EvolutionAgent —— 演化分析

```
agent_id:     evolver
模式:         Federated
意图:         EVOLUTION_ANALYSIS
LLM:          无（纯算法）
依赖:         无
```

**职责**：对比两个图谱快照 → 新增/删除/修改三态标注。

**输入/输出**：
```
输入: {snapshots: [{snapshot_id, skills: {name: {confidence}}}]
输出: {added_skills: [...], removed_skills: [...], modified_skills: [{name, old, new}],
       summary: "新增X/删除Y/修改Z"}
```

---

### 3.9 OrchestratorAgent —— 调度中心

```
agent_id:     orchestrator
模式:         Collaborative
意图:         PIPELINE
LLM:          无
依赖:         无
```

**职责**：处理复杂任务（PIPELINE、多意图）→ 任务分解 → 调度 → 结果整合。

**任务分解策略**：
- 单意图 → 直接路由到对应 Agent
- 依赖链意图（如 MATCH_POSITION）→ 按依赖图展开为 [extractor, normalizer, matcher]
- 辩论意图（如 DISCOVER_ROLE）→ [discoverer, judge]

## 4. 基础设施组件

### 4.1 AgentRegistry（单例）
- `register(agent)` → 存入 `_agents` + `_intent_map[intent] = agent_id`
- `get_by_intent(intent)` → 返回 Agent 实例
- `can_execute(agent_id, completed)` → 检查依赖是否满足
- `get_federated() / get_collaborative()` → 按模式筛选

### 4.2 IntentRouter
- `route(intent)` → intent → agent_id 静态映射
- `get_chain(agent_id)` → 返回前置依赖链
- 17 条意图映射，7 条依赖链

### 4.3 AgentExecutor（单例）
- `execute(intent, payload)` → 联邦式直接执行，协作式按链执行
- `execute_pipeline(intent, items, agent_ids)` → 批量 MapReduce 模式

### 4.4 SharedContext（单例）
- 命名空间隔离：`user_profiles / pipeline_cache / task_states / session_data`
- `cache_pipeline(key, value)` → 带时间戳缓存
- `get_session(session_id, key)` → 会话数据读取

### 4.5 MultiAgentSystem（单例入口）
- `initialize(llm_client)` → 创建 9 个 Agent 实例并注册
- `process(intent, payload)` → 委托给 Executor
- `process_pipeline(items, agent_ids)` → 批量处理

## 6. 与参考系统的关键差异

| 维度 | 参考系统（ai对话助手） | 我们的系统 |
|------|----------------------|-----------|
| 触发方式 | 自然语言 → 关键词意图识别 | API 端点 → 静态意图映射 |
| 通信方式 | MessageBus 异步发布订阅 | SharedContext + state 传递 |
| LLM 集成 | LangChain Agent + tools | 直接调用星火 OpenAI SDK |
| 协作深度 | Federated/Collaborative/Workflow DAG | Federated/Collaborative + 辩论 |
| 状态管理 | `MultiAgentState` (TypedDict + Reducers) | `MultiAgentState` (dataclass) |
| Agent 数量 | 15+ | 9 |
| 持久化 | Supabase | MySQL |
