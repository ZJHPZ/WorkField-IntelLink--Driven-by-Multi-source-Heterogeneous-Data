## 1. 项目背景与重构动机

### 1.1 原有后端问题

原 `职域智联图谱/backend/` 实现与 `设计方案_v2.md` 之间存在严重鸿沟：

| 问题 | 详情 |
|------|------|
| **多智能体框架是空壳** | 6 个 Agent 的 `execute()` 只是转发 pipeline 函数的薄 wrapper，`think()` 返回硬编码字符串，LLM 零参与 |
| **To B / To C 完全缺失** | 设计方案 §7 定义的企业+个人双工作台一行代码都没有 |
| **图谱只有内存 dict** | 无 Neo4j / PostgreSQL，KnowledgeGraph 是一个 dataclass |
| **API 只有 6 个通用端点** | 缺简历解析、人岗匹配、JD 诊断、职业规划等全部业务端点 |
| **无 Docker** | 赛题明文要求 Docker Compose 一键部署，完全没有 |
| **评测体系残缺** | 只有 JD 解析准确率，缺简历提取和匹配准确率 |
| **Agent 协作模式从未调用** | DEBATE / CONSENSUS 模式代码存在但零使用 |

### 1.2 重构目标

在 `后/` 目录从零重写后端，100% 对齐 `设计方案_v2.md` + 赛题评分要求。

### 1.3 设计总纲（来自设计方案 v2）

> "每一个技能点都能溯源，每一次演化都有证据，每一个新岗位都从数据里长出来，而不是从模型嘴里编出来。"

三条设计主线：
- **可溯源**：每个技能、每条关系都能回溯到真实 JD 证据
- **可演化**：图谱有版本、有快照、有 diff、有动态指标
- **双主体**：同一底座，企业侧招人/定标准，个人侧规划成长

## 7. 多智能体设计（Phase 2 实现）

### 7.1 核心原则

- Agent **不再做薄 wrapper**——每个 Agent 拥有独立的 LLM 推理能力
- 关键决策点引入 **辩论+裁决**（DEBATE 模式），普通流程用 PIPELINE
- 去掉 MessageBus 和 AgentState 状态机——Agent 通过共享 context dict 通信

### 7.2 Agent 协作模式

```
                    ┌─────────────┐
                    │ Orchestrator│
                    └──────┬──────┘
                           │
        ┌──────────────────┼──────────────────────┐
        │                  │                      │
   ┌────▼────┐      ┌──────▼──────┐        ┌─────▼─────┐
   │ PIPELINE│      │   DEBATE    │        │ CONSENSUS │
   │ (串行)  │      │ (正反+裁决)  │        │ (投票)    │
   └────┬────┘      └──────┬──────┘        └─────┬─────┘
        │                  │                      │
   ExtractAgent      DiscoveryAgent(X2)      NormalizeAgent
   → VerifyAgent     → SkepticAgent          + 多源信号
   → NormalizeAgent  → JudgeAgent             (投票 ≥2/3)
   → EvolutionAgent
   → SuggestAgent
```

### 7.3 关键辩论点

**辩论点 1：新岗位发现**
- DiscoveryAgent 分析新兴技能聚类 → 提出候选岗位定义
- SkepticAgent 独立审查：JD 条数够不够？只是旧岗位换名？薪资合理吗？
- JudgeAgent 裁决：Confirmed / Pending / Rejected

**辩论点 2：技能置信度（Consensus 模式）**
- JD / GitHub / arXiv / 标准 各自独立评分
- ≥2 源确认 → confirmed，单一源 → candidate
- 命中设计方案 §3.4 "孤证不入图谱"

### 7.4 Agent 基类接口

```python
class BaseAgent:
    def execute(self, context: dict) -> None:
        """从 context 读取输入，处理后将结果写回 context。"""
    
    def llm_reason(self, prompt: str, system: str = "") -> str:
        """调用 LLM 进行推理（Agent 自己的 LLM 能力）。"""
```

## 9. 六层流水线详解

### L1 数据层 ✅
- **清洗**（`l1_clean.py`）：正则抽薪资/经验/学历 + 段落定位 + L0 噪声过滤
- **分级归类**（`l1_clean.py`）：L0 丢弃 / L1 泛化软技能降权 / L2 岗位软技能 / L3 硬技能
- **分段**（`l1_segment.py`）：纯文本 JD → 按标题行推断段落类型

### L2 融合层（Phase 2）
- **去重**（`l2_dedup.py`）：SimHash 近重复检测
- **归一化**（`l2_normalize.py`）：种子别名映射 + embedding 聚类
- **置信度**（`l2_confidence.py`）：`confidence = sigmoid(w1·log(1+DF) + w2·Σ(信源权重) + w3·位置权重 + w4·时间新鲜度 - w5·通胀惩罚)`
- **共现**（`l2_cooccurrence.py`）：技能对共现强度
- **动态指标**（`l2_metrics.py`）：新兴度/衰退度/波动率/演化速度/半衰期/通胀指数

### L3 智能层 ✅（抽取+闸门）/ P2（Agent 系统）
- **抽取**（`l3_extract.py`）：LLM（星火）优先 + 规则兜底，每个技能带 evidence 溯源
- **幻觉闸门**（`l3_verify.py`）：三道闸（强制引证→证据核验→内容核验），输出拦截率
- **新岗发现**（Phase 2）：三段式（趋势源候选→需求源验证→权威源定义）
- **演化 diff**（Phase 2）：快照对比 → 增/删/改三态

### L4 图谱层 ✅
- **建图**（`l4_graph.py`）：Position/Skill/Evidence 节点 + REQUIRES/SUPPORTED_BY/BELONGS_TO 关系写入 Neo4j
- 孤证标 candidate，confidence≥0.55+多源标 confirmed

### L5 应用层 ✅（基础端点）/ P3（业务端点）
- FastAPI REST API，25+ 端点
- 图谱 → AntV G6 数据格式
- 匹配引擎 / 简历解析（Phase 3）

### L6 主体层（Phase 3）
- 企业侧：JD 诊断 / 团队盘点 / 人才预测 / 岗位标准管理
- 个人侧：差距分析 / 学习路径 / 半衰期提醒 / 转行可行性

## 12. 关键设计决策

1. **Agent 不引入 LangChain/LangGraph**：自研轻量 Orchestrator，避免重型框架依赖，竞赛场景可控性优先
2. **Neo4j 驱动版本**：使用 neo4j 6.x（最新稳定版），异步驱动，execute_query 简化 API
3. **MySQL → PostgreSQL**：设计方案 v2 明确指定 PostgreSQL（MySQL 是旧实现的偏离），纠正回来
4. **Phase 3 端点目前返回 501**：20 个业务端点已挂载但返回 501 Not Implemented，确保 API 文档完整，实现按 Phase 推进
5. **数据路径**：`config.py` 中 `DATA_DIR` 指向原 `职域智联图谱/data/`，数据文件不迁移
6. **`.env` 不提交**：已在 `.gitignore` 中，模板在 `.env.example`
