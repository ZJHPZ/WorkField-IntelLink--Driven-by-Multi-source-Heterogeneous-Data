## 2. 数据模型

### 2.1 PositionStandard（企业自定义岗位标准）

> 存储于 MySQL `position_standards` 表。与图谱中的 Position 节点是 1:1 映射——Position 是市场数据抽取的结果，PositionStandard 是企业在此基础上的人工定义。

```sql
CREATE TABLE position_standards (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    position_id     VARCHAR(64) NOT NULL UNIQUE,      -- 对应图谱 Position.position_id
    name            VARCHAR(256) NOT NULL,             -- 岗位名称
    tech_stack      VARCHAR(64) NOT NULL,              -- 技术栈 (AI/大数据/智能系统/物联网)
    status          ENUM('candidate','under_review','confirmed','active','deprecated') DEFAULT 'candidate',
    version         INT DEFAULT 1,                     -- 版本号（每次更新递增）
    core_responsibility TEXT,                          -- 核心职责描述
    industry_scenarios  JSON,                          -- ["场景1", "场景2"]
    created_at      DATETIME DEFAULT NOW(),
    updated_at      DATETIME DEFAULT NOW(),
    updated_by      VARCHAR(64)                        -- 操作人
);

CREATE TABLE position_standard_skills (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    standard_id     INT NOT NULL,
    skill_name      VARCHAR(128) NOT NULL,             -- 规范技能名
    required_type   ENUM('必备','加分') DEFAULT '必备',
    confidence      DECIMAL(4,3) DEFAULT 1.0,          -- 企业自定义置信度 (非市场置信度)
    evidence_refs   JSON,                              -- ["ev::1", "ev::2"] 关联证据
    sort_order      INT DEFAULT 0,
    FOREIGN KEY (standard_id) REFERENCES position_standards(id)
);
```

### 2.2 EvolutionChangelog（岗位标准变更审计日志）

```sql
CREATE TABLE evolution_changelog (
    id              INT PRIMARY KEY AUTO_INCREMENT,
    position_id     VARCHAR(64) NOT NULL,
    position_name   VARCHAR(256),
    snapshot_old    VARCHAR(64),                       -- 旧快照 ID
    snapshot_new    VARCHAR(64),                       -- 新快照 ID
    change_type     ENUM('added','removed','modified') NOT NULL,
    skill_name      VARCHAR(128) NOT NULL,
    field_changed   VARCHAR(64),                       -- 哪个字段变了 (required_type/confidence/name)
    old_value       VARCHAR(256),
    new_value       VARCHAR(256),
    data_source     VARCHAR(256),                      -- "市场JD数据 2026Q3 / 人工优化"
    manual_optimized BOOLEAN DEFAULT FALSE,            -- 是否人工操作
    operator        VARCHAR(64),                       -- 操作人
    created_at      DATETIME DEFAULT NOW(),
    INDEX idx_position (position_id),
    INDEX idx_created (created_at)
);
```

### 2.3 Position 生命周期状态机

```
candidate ──→ under_review ──→ confirmed ──→ active ──→ deprecated
   │               │               │             │
   └───────────────┴───→ rejected ←┴─────────────┘

状态转换规则:
  candidate → under_review: HR 点击"验证"
  under_review → confirmed: JudgeAgent 裁决 Confirmed + HR 确认
  under_review → rejected:  JudgeAgent 裁决 Rejected
  confirmed → active:       HR 发布标准
  active → deprecated:      岗位不再招聘（手动标记）
  active → under_review:    新一轮市场差异超过阈值，触发重新审查
```

## 3. 功能需求详设

### FR-1 新岗位发现与定义

#### FR-1.1 新岗位信号发现

```
触发方式: 定时任务（每批数据入库后自动运行）或手动触发

数据流:
  L2动态指标(emergence > 0.5) 
  → 新兴技能列表 
  → HDBSCAN聚类 
  → 候选岗位 Term

输入: 无（系统自动）
处理:
  1. 从 L2 指标获取 emergence > 0.5 的技能
  2. 对这些技能做共现聚类（来自 l2_cooccurrence）
  3. 对每个聚类，回 JD 库检索确认出现次数
  4. 过滤: JD < 3 条的聚类丢弃
  
输出 Schema:
{
  "candidates": [
    {
      "candidate_id": "cand-001",
      "term": "AI提示词工程师",
      "emerging_skills": [
        {"name": "Prompt Engineering", "emergence": 0.85},
        {"name": "Few-shot Learning",  "emergence": 0.72}
      ],
      "jd_count": 15,
      "first_seen": "2026-05-15",
      "status": "待验证",
      "confidence": 0.65
    }
  ],
  "total": 3,
  "generated_at": "2026-08-02T10:00:00"
}
```

#### FR-1.2 候选岗位验证（人工 + AI 辩论）

```
API: POST /api/enterprise/positions/validate

Request:
{
  "term": "AI提示词工程师",
  "emerging_skills": ["Prompt Engineering", "Few-shot Learning", "Chain-of-Thought", "RLHF"],
  "evidence_jds": [
    {"jd_id": "jd-001", "title": "提示词工程师", "full_text": "负责LLM提示词设计与优化..."},
    ...
  ]
}

Agent 辩论流程:
  Step1: DiscoveryAgent.process(state)
    → 分析 JD 证据 + 新兴技能
    → 调用星火 LLM 生成 5 字段定义
    → state.set_agent_result("discoverer", {definition, evidence_count, skill_count})

  Step2: 系统内置反方审查（Skeptic 逻辑）:
    → 规则层: 检查 JD 数量 (< 5 → high concern)
    → 规则层: 检查技能可区分性 (< 3 必备技能 → high concern)
    → 写入 state.payload["con_argument"]

  Step3: JudgeAgent.process(state)
    → 综合正反双方论点
    → → LLM 增强裁决
    → 输出 verdict + reason + next_steps

Response:
{
  "status": "ok",
  "term": "AI提示词工程师",
  "verdict": {
    "verdict": "Confirmed",
    "reason": "12条JD+7项技能，通过市场验证",
    "evidence_count": 12,
    "skill_count": 7,
    "high_concerns": 0,
    "next_steps": ["列入候选库", "持续收集JD"],
    "definition": {
      "岗位名称": "AI提示词工程师",
      "核心职责": {"value": "负责LLM提示词设计与优化...", "confidence": 0.85},
      "必备技能": {"value": ["Prompt Engineering", "Few-shot Learning", "Chain-of-Thought"], "confidence": 0.82},
      "加分技能": {"value": ["RLHF", "多模态提示"], "confidence": 0.70},
      "典型行业应用场景": {"value": ["AI应用开发", "LLM产品"], "confidence": 0.75}
    }
  }
}

人工操作:
  PUT /api/enterprise/positions/{id}/standard
  → HR 修改技能列表 / 调整必备加分 / 编辑职责描述
  → 写入 evolution_changelog (manual_optimized=true)
  → position_standards.status → 'active'
```

#### FR-1.3 新岗位 5 字段定义（赛题要求①逐字对齐）

```
每个确认的新岗位必须包含且仅包含以下 5 字段:

① 岗位名称:         string, 规范名, 来自市场 JD 高频词
② 核心职责:         {value: string, confidence: float, evidence_ids: [str]}
③ 必备技能:         {value: [str], confidence: float, evidence_ids: [str]}
④ 加分技能:         {value: [str], confidence: float, evidence_ids: [str]}  
⑤ 典型行业应用场景:  {value: [str], confidence: float, evidence_ids: [str]}

每条带 confidence + evidence_ids + 状态:待人工确认
支持人工优化入口 (PUT /api/enterprise/positions/{id}/standard)
```

诊断算法（enterprise_service.diagnose_jd）:
  技能数量异常: skill_count > avg_skill_count * 1.5 → +0.4 通胀分

## 5. 数据库查询规范

### 5.1 Neo4j 关键查询

```cypher
// 查询岗位的所有技能及证据
MATCH (p:Position {position_id: $pid})-[r:REQUIRES]->(s:Skill)
OPTIONAL MATCH (s)-[:SUPPORTED_BY]->(e:Evidence)
RETURN p, collect({skill: s, relation: r, evidences: collect(e)[..5]}) AS skills

// 查询新兴技能 (emergence > 0.5)
MATCH (s:Skill) WHERE s.emergence > 0.5
RETURN s ORDER BY s.emergence DESC LIMIT 20

// 查询技能共现关系
MATCH (a:Skill)-[r:CO_OCCURS]-(b:Skill) WHERE r.strength > 0.3
RETURN a.name, b.name, r.strength
```

### 5.2 MySQL 关键查询

```sql
-- 岗位标准变更历史
SELECT * FROM evolution_changelog
WHERE position_id = 'pos::java-engineer'
ORDER BY created_at DESC LIMIT 50;

-- 统计人工优化比例
SELECT 
  COUNT(*) AS total_changes,
  SUM(manual_optimized) AS manual_count,
  ROUND(SUM(manual_optimized)/COUNT(*)*100, 1) AS manual_pct
FROM evolution_changelog;
```
